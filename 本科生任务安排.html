本科生任务安排 · 九轴游戏化多运动状态数据采集系统

游戏名《魔法岛大冒险》；系统定位：基于九轴 IMU 的儿童游戏化多运动状态数据采集系统。架构 WT901 → Python（数据层）→ Unity（游戏层）：你负责九轴接入/通信/解析/保存，本科生只负责 Unity 游戏交互与事件回传。本科生搭的是真实人体 IMU 数据采集基础设施，算法（Qa/Qm/融合）归你。

1. 三层架构（职责分工的核心）

Sensor Layer

2. 数据流与双向通信

                ┌── WT901 Reader ──┐
                │                  │
Input Mode ─────┤                  ├→ Unified IMU JSON → UDP:5005 → Unity
                │                  │                     └→ CSV (Python 主记录)
                └── Simulator ─────┘
                                         ↑
                              UDP:5006 ← Unity 回传 game_event
  • Python → Unity：每帧统一 JSON（roll/pitch/yaw/ax…/motion_state/source），50 Hz。
  • Unity → Python：瞬时事件 {"event":...,"task_id":...,"trial_id":...} 回传，Python 写入同一 CSV。
  • Unity 永远不关心 source 是 SIM 还是 REAL，只取 roll/pitch/yaw/加速度做游戏。

3. 四个核心实验阶段（覆盖 5 类运动状态）

不再做"5 个独立游戏/5 个场景"。整个游戏就是一个魔法岛 + 4 个任务区域，只改变提示与控制方式，不切完全不同的美术与逻辑。本科生只需维护：一套角色、一个地图、一个 IMU 管理器、一个数据记录器、一个任务状态机。

阶段儿童动作科研变量motion_state对应原方案
Task 1 风之谷（倾斜）前后左右倾斜魔杖Roll / Pitch、重力分量TILTA 倾斜迷宫
Task 2 迷雾灯塔（旋转）绕竖轴左右转魔杖Yaw、Gz、航向漂移ROTATEB 旋转驾驶
Task 3 巨石林（动态）上/下/左/右/摇（标准化幅度）高频 Acc/Gyro、高动态SHAKEC 节奏摇晃
Task 4 水晶洞（空间+静态）走 P0→P1→P2→P3→P0，每点静止 2 sMag/位置/空间相关性、返回恢复MOVE + STATICE 魔法寻宝
📌 静态（STATIC）不单独成任务：嵌入 Task 1 末尾（"能量补充，保持不动 3 秒"）与 Task 4 各定点（静止 2 s）。于是 4 Tasks → 5 Motion States：TILT → ROTATE → SHAKE → STATIC → SPATIAL/MAG。

4. 数据格式约定（必须定死）

Python 主记录 CSV 表头（每行一帧）：

frame_id, device_timestamp_ms, host_timestamp_ms,
ax,ay,az, gx,gy,gz, mx,my,mz,
roll,pitch,yaw,
motion_state, phase,
event, task_id, trial_id, source
  • frame_id：帧序号，查丢包用（Loss = N_expected − N_received）。
  • device_timestamp_ms / host_timestamp_ms：设备侧（若有）与主机侧时间戳，可研究 WiFi 延迟与同步。
  • motion_state / phase：连续状态标签（TILT/ROTATE/SHAKE/STATIC/MOVE），比 event 更重要，是 Qa/Qm 的核心输入。
  • event：瞬时事件（TASK_START、GATE_PASS、STATIC_OK、ZONE_P1、TASK_END…），来自 Unity 回传。
  • trial_id：同一被试重复次数（trial_01/02/03）。source：SIM_AUTO / SIM_KEYBOARD / WT901，一眼区分真假数据。
  • 采样率目标 ≥ 50 Hz（以实际输出为准）。
event（瞬时）触发task_id
SESSION_START / SESSION_END开始/结束采集0
TASK1_START, TILT_FLY, GATE_PASS, TASK1_END进山谷/飞行/过星门/完成1
TASK2_START, ROTATE_NAV, ROCK_DODGE, LIGHTHOUSE_REACH, TASK2_END出海/转向/避礁/到灯塔2
TASK3_START, SWING_UP/DOWN/LEFT/RIGHT/SHAKE, BOULDER_SMASH, TASK3_END动作提示/击碎3
TASK4_START, MOVE_TO_P1/P2/P3, STILL_2S, RETURN_P0, TASK4_END移动/静止2秒/返回4

5. 验收标准：Motion State Coverage

统一验收对象为运动状态覆盖度，不是"游戏数量"。必须完成 4 个核心阶段，并覆盖至少 5 类运动状态：倾斜、旋转、高动态、静态、空间/磁场变化。本科生问"做 4 个算完还是 5 个"——答案是看覆盖度。

8. 模拟数据模式（关键：本科生不等 WT901 也能开发）

你已决定采用 Python 模拟器：Unity 永远不知道数据是 SIM 还是 REAL，统一 JSON over UDP。切换真机只需把 produce_packet() 换成 WT901 解析结果，Unity 零改动。

模式说明用途
SIM_AUTO自动循环 TILT→ROTATE→SHAKE→STATIC 标准波形回归调试，每次输入一致
SIM_KEYBOARDA/D=roll, W/S=pitch, Q/E=yaw, 空格=shake本科生手动测试游戏手感
REAL换成 WT901 实测（你实现后切 MODE）真机采集

已提供两份可直接运行的文件：

  • imu_simulator_v01.py —— Python 模拟器（自动 + 键盘两模式，含回传接收与 CSV 主记录）。运行：python imu_simulator_v01.py 或加 KEYBOARD。
  • unity/IMUReceiver.cs —— Unity 接收/回传脚本，挂到空 GameObject 即可；游戏脚本读 latest.roll/pitch/yaw，状态机调 SendEvent("GATE_PASS", 1)。
⚠️ 模拟器只解决"没传感器时游戏也能开发"，不模拟 gyro bias / hard-iron / 噪声 / 温漂 / 磁扰 / 饱和——那些是你的科研问题。

10. 给本科生的启动指令（可直接转发）

第一步（用模拟器，不用等真机）：
1. 装好 Unity（已完成）。
2. 运行 python imu_simulator_v01.py KEYBOARD （会自动发 UDP 数据）。
3. 在 Unity 挂上 IMUReceiver.cs，确认能收到 roll/pitch/yaw 并驱动一个方块旋转。
4. 把 roll/pitch 映射到角色左右/上下移动，yaw 映射到转向。
5. 用 SendEvent(...) 在关键节点回传事件（过星门、静止完成等）。
跑通这步再做正式游戏场景（魔法岛 4 个任务区域）。
