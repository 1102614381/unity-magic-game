彦祖 · 本周任务（实验会话管理界面）

数据层已跑通（模拟器 UDP + Unity 接收就绪），本周在游戏内容最终确定前，先搭"实验会话管理"界面。注意：这不是给孩子用的华丽登录页，而是给实验员用的被试与场次管理。

本周总目标：做一个实验员用的开始界面——输入/选择被试编号、认知游戏、trial，点开始进入游戏；结束能把这些信息回传给 Python 并写进 CSV。界面用 Unity 默认 UI 控件即可，不花时间做美术。
任务 1

理解"为什么现在做这个"

约半天
  • 重读 九轴游戏项目说明.html 的"六、最终数据流程"和"七、验收标准"。
  • 理解：真实实验要区分不同孤独症儿童被试和多次 trial，所以需要在游戏开始前由实验员录入信息。这不是账号系统，是实验会话管理。
  • 重点记住要落地的字段：child_id、trial_id、task_id。
任务 2

搭实验员设置界面

约 1–2 天
  • 在 Unity 里新建一个 开始/设置场景（Canvas + UI），包含：
    • 被试编号 child_id：用下拉选择或数字输入（避免手输出错）。
    • 选择认知游戏/任务 task_id：先留 4 个占位按钮（感知平衡 / 注意力 / 社交 / 记忆），后面接具体场景。
    • 选择 trial trial_id：trial_01 / 02 / 03 下拉。
    • 「开始实验」按钮 → 进入游戏场景（本周先用之前那个会转的 Cube 占位）。
    • 「结束并保存」按钮。
  • 风格：大按钮、少文字、简洁即可（导师要求"减少操作步骤、流程化"）。
任务 3

把会话信息回传 Python

约 1 天
  • 点「开始实验」时，把 child_id / trial_id / task_id 通过 IMUReceiver.cs 已有的回传通道（UDP 5006）发给 Python。
  • 让 Python 把这些信息写进 CSV（表头或每帧都带），这样后面拿到的数据天然带被试和场次。
  • 参考已有的事件回传写法，新增几个事件如 SESSION_START、SELECT_TASK。
任务 4

最小流程 demo + 提交

约半天
  • 跑通流程：实验员填编号 → 选任务 → 开始 → 游戏场景（Cube 占位）→ 结束保存。
  • 截图/录屏发给师姐确认。
⚠️ 三个避坑：
① 不要做账号密码系统——这是实验员前置设置，不是用户注册；
② 不要花一周做美术——用 Unity 默认 UI 控件，先把功能跑通；
③ 游戏内容还没定，所以界面要"可复用"：任务选择先留占位按钮，后面接具体场景时再替换，不要写死。
💡 后续硬性要求（先记着，本周不做）：导师要求游戏必须有正向反馈（得分 / 金币 / 小红花）和流程化、少思考的交互。这些是你之后做具体认知游戏时要满足的。
