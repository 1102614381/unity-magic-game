九轴 IMU 儿童体感数据采集游戏 · 设计需求说明书

面向儿童运动感知研究的「体感游戏 + 九轴数据采集仪」设计草案 ｜ 设备：WT901WIFI 九轴惯性测量单元 ｜ 版本 v0.1（需求稿）

1. 背景与设计目标

本游戏服务于课题《面向多场景感知的低功耗 IMU 边缘智能感知芯片关键技术研究》中的儿童运动感知应用场景。当前课题以 WT901WIFI 商业九轴 IMU 为平台，重点研究动态运动条件下的姿态误差、漂移、磁扰动与自适应融合。我们需要一种能让孩子自然、持续、可控地产生多样运动的数据采集手段。

三个本科项目（见 PPT）均为临床康复导向游戏：①上肢康复游戏（恩祈，含登录/注册、动腿吃金币类交互、难度关卡、数据后台）；②下肢 CPM 机器康复游戏（读电机角度）；③Unity 语音训练游戏（语音评估/CER）。本设计与之互补不重复：它们面向患者康复，本游戏面向健康儿童，把九轴 IMU 当作体感手柄，让儿童在玩的过程中产出覆盖多运动模态的科研数据。

🎯 一句话定位：「披着游戏外衣的九轴数据采集仪」——孩子以为是玩游戏，研究者拿到的是带时间戳、带动作标签、覆盖姿态/漂移/磁扰动场景的高质量九轴数据集。

设计目标（验收视角）

  • 数据价值优先：玩法设计的第一性原则是「尽量覆盖更多运动模态」，而非单纯好玩。
  • 儿童可用：3–12 岁，图标化、无文字依赖、3 分钟内上手。
  • 科研可用：被试管理、方案配置、实时质控、一键导出、常规组/对照组分组。
  • 可解释：每个关卡/动作都能映射到具体要采集的九轴信号特征。

2. 产品定位与技术栈

用户角色

儿童（玩家） 3–12 岁，操作 IMU 体感手柄/佩戴物。
研究者 / 实验员 配置方案、监控采集、导出数据。
（可选）家长 查看训练/游戏报告。

硬件与佩戴

WT901WIFI 九轴 IMU（加速度+陀螺仪+磁力计）。佩戴方式按关卡切换：手腕环 / 脚踝带 / 手持魔杖。WiFi/TCP 或串口回传，采样率建议 ≥100 Hz。

技术栈建议

为与本科项目协同，首选 Unity + C#：可直接复用恩祈项目的登录/注册界面与数据后台模板。IMU 数据通过 WiFi/TCP 或串口插件接入；姿态解算（roll/pitch/yaw）可用内部融合或回传设备原始九轴由离线融合。

轻量替代：Web + WebSocket 前端（儿童界面用 Three.js 做 3D 场景），后端 Node/Python 收数。便于跨平板/大屏部署。

与本科项目复用点

  • 登录/注册管理界面（参考恩祈上肢康复游戏）
  • 数据后台管理界面（展示训练/采集效果）
  • 难度关卡机制

3. 核心功能需求

3.1 研究者侧（采集控制台）必做

功能说明
被试档案管理儿童 ID、年龄、性别、分组（常规组 / 对照组）、备注；与量表系统打通（见 PPT 的问卷/量表管理）。
实验方案配置勾选本次要玩的关卡组合、单关时长、采样率、是否开启「磁扰动提示」（靠近金属/电器）。
实时监测面板九轴数值实时曲线 + 3D 姿态模型（立方体随 roll/pitch/yaw 转动）+ 信号质量/掉线/磁扰告警。
采集与同步开始/暂停/结束；每条数据带时间戳与游戏事件标签（关卡ID、动作类型、得分）。
数据导出CSV / .mat / JSON；按被试+日期归档；含原始九轴 + 派生姿态 + 事件流。
数据质量评估覆盖率、掉点数、磁扰段标记、运动范围（各轴 min/max）是否达标。

3.2 儿童侧（玩法）必做

体感控制映射：倾斜→roll/pitch、旋转→yaw、摇晃/挥动→加速度与角速度动态段、静止保持→静态基线（测漂移）。关卡设计以「运动模态覆盖」为第一原则：

关卡玩法主要采集的九轴信号科研用途
A 倾斜迷宫倾斜手柄让小球穿过迷宫roll/pitch 中低速变化、重力分量姿态解算精度
B 旋转驾驶左右旋转驾驶飞船躲障碍yaw 大角度旋转、z 轴陀螺航向误差/漂移
C 节奏摇晃跟着音乐摇晃收集星星高频加速度/角速度动态高动态姿态误差
D 平衡挑战保持姿势不动撑住桥梁近静态段（含微小抖动）零速/静态漂移
E 魔法手势磁扰画圈/挥动施法，场景靠近电器磁力计异常 + 复合运动磁扰动鲁棒性

反馈与留存：星星奖励、音效、卡通动画、进度条；难度自适应（按动作完成度调速度/目标）。

5. 标准采集流程

步骤动作说明
1连接与校准WiFi/串口连接 WT901WIFI；静置 2 秒做零偏/磁力计粗校准；佩戴方式确认（手腕/脚踝/手持）。
2选择被试与方案研究者端选儿童档案 + 分组 + 关卡组合 + 采样率。
3儿童开始游戏图标选角色 → 进入关卡；实时姿态小窗让孩子看见自己的动作被"看见"。
4实时监控研究者端看九轴曲线 + 3D 模型 + 告警；磁扰/掉点即时标记。
5结束与质检结束采集 → 自动质检（覆盖率/异常段）→ 不合格可重采对应关卡。
6导出与归档导出 CSV/.mat，按 被试+日期 归档；可选同步到量表/问卷管理系统。

6. 验收指标（建议）

  • 采样：≥100 Hz，时间戳精度 ≤10 ms，丢包率 <1%。
  • 覆盖：单次完整流程须触发 A–E 全部 5 类运动模态（倾斜/旋转/摇晃/静态/磁扰）。
  • 同步：游戏事件标签与九轴数据时间对齐误差 <50 ms。
  • 可用：3–12 岁儿童在无人指导情况下 5 分钟内可独立开始游戏。
  • 科研：导出数据可直接用于姿态解算、漂移、磁扰动与融合算法评估。

7. 技术实现建议（落地路线）

路线 A：Unity（推荐，与本科项目一致）

  • IMU 接入：WT901WIFI 通过 WiFi/TCP 或串口，用 C# 异步接收原始九轴帧。
  • 姿态：设备可回传融合角；研究侧建议同时保存原始九轴，离线用自研/对比融合算法评估。
  • 复用：恩祈项目的登录/注册 UI、数据后台模板直接改造成研究者控制台。

路线 B：Web + WebSocket（轻量、易跨屏）

  • 前端 Three.js 做 3D 场景与角色，儿童界面跑在平板/大屏浏览器。
  • 后端 Python/Node 收数、打标签、写 CSV；可对接量表系统 API。
💡 磁扰动是课题重点：关卡 E 故意安排在有金属/电器环境，并在研究者端对 mag_flag 打标，便于后续评估自适应融合对磁扰的抑制效果。

8. 与三个本科项目的协同与边界

本科项目定位本游戏的边界（不重复）
上肢康复游戏患者上肢康复，含登录/注册、交互、数据后台面向健康儿童；复用其 UI 模板而非重做；数据目标是科研九轴而非康复疗效。
下肢 CPM 康复游戏读取 CPM 电机角度本游戏用 IMU 自采，不依赖 CPM 机构。
Unity 语音训练游戏语音评估/CER本游戏不涉及语音，专注运动模态。
（PPT）量表/问卷系统常规组/对照组、量表导入、可视化报告本游戏的被试分组与导出应与其打通，形成「游戏采数 + 量表评估」闭环。
