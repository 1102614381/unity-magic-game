四个认知训练游戏 · 一页式设计说明

面向 6–9 岁孤独症儿童 · 同一套九轴魔法棒交互 · 供本科生延伸开发。每游戏一页，固定 6 项：游戏目标 / 认知训练目标 / 操作方式 / 反馈 / 难度 / 记录指标。统一数据契约见文末。

总原则：游戏提供训练任务并记录行为表现，但不能仅凭单 IMU 运动数据声称证明了注意力/记忆/社交等认知能力改善——效果仍需合适的任务指标与后续评估。儿童游戏是你的应用验证场景，IMU 研究主线（Calibration → Motion State → Qa/Qm → Adaptive Fusion）不变。
统一交互映射（供四个游戏复用）： Roll → 左右Pitch → 前后Yaw → 水平旋转/指向Shake → 确认/施法Static → 稳定/等待
游戏1

星星平衡岛

感知与动作协调

🎯 游戏目标

倾斜魔法棒，控制小球/飞船沿指定路线前进，避开障碍，最终到达终点收集星星。

🧠 认知训练目标

感知与动作协调、视觉-运动协调、操作稳定性。
注意：单手持棒主要评价手部姿态控制与操作稳定性，不等同于直接评价全身姿势平衡。

🕹 操作方式

Roll/Pitch 控制移动方向；Ax/Ay/Az 可判断运动平稳性。倾斜越大移动越快（灵敏度可调）。

🎉 反馈

到达终点 → 星星/小红花特效+音效；碰到障碍 → 温和提示并回退/重来；顶部实时进度条与剩余时间。

📶 难度

路线复杂度、障碍密度、限时长短、移动灵敏度分级（4 档）。支持提示/暂停，避免强制倒计时。

📊 记录指标

完成时间、偏离目标次数、运动平稳性（加速度方差）、姿态变化范围、完成率、碰障次数。

游戏2

寻找魔法精灵

注意力

🎯 游戏目标

屏幕出现多个不同颜色的魔法精灵；系统提示"请找到蓝色精灵"，玩家旋转魔法棒控制指针/视角，找到目标并保持指向一定时间。

🧠 认知训练目标

选择性注意（从干扰中找目标）+ 持续注意（保持指向）。具体采用哪种，由研究者定稿。

🕹 操作方式

Yaw 旋转控制指针/视角；Roll/Pitch 微调指向；Gyro 作为旋转参考。找到后 Shake 确认。

🎉 反馈

找到目标 → 高亮+音效；误选 → 温和提示；指向稳定计时环填充，满则成功。

📶 难度

干扰精灵数量、与目标相似度、需保持指向的时长、时间限制分级。

📊 记录指标

首次找到目标时间、误选次数、目标选择准确率、指向稳定性、任务完成时间。

游戏3

帮助森林伙伴

社交情境理解

🎯 游戏目标

卡通伙伴出现情境（如：难过的小兔找不到玩具），给出 2–3 个简单选项，玩家倾斜/旋转选择，挥动魔法棒确认。

🧠 认知训练目标

基础社交线索识别与情境选择。社交属性来自情境与选择内容，不是靠"挥动动作"产生；IMU 只承担交互输入角色。

🕹 操作方式

Roll/Pitch 或左右旋转在选项间移动光标；Shake 确认选择。选项用大图标+图形，少文字。

🎉 反馈

选择后伙伴表情变化；正确帮助 → 开心动画+星星；不当选择 → 温和引导而非惩罚。

📶 难度

选项数量（2→3）、情境复杂度、是否需要提示、是否限时分级。

📊 记录指标

选择结果、决策反应时、提示次数、完成率、重复尝试次数。

游戏4

魔法记忆森林

工作记忆

🎯 游戏目标

屏幕依次出现方向提示（如 左→右→前），玩家记住顺序后，依次移动魔法棒到对应方向节点完成动作。

🧠 认知训练目标

视觉序列记忆、顺序执行（工作记忆）。是下面最小原型的实现对象。

🕹 操作方式

Roll（左右）/Pitch（前后）移动小球到方向节点；按展示顺序依次到达。可选 Shake 作为"确认一步"。

🎉 反馈

每步正确 → 节点亮起+音效；错误 → 该序列重来（不惩罚）；整序列完成 → 魔法特效+星星奖励。

📶 难度

序列长度（2→5）、方向数量、展示速度、节点间隔时间分级。

📊 记录指标

正确动作数、顺序正确率、每步反应时、提示依赖次数、重复次数、目标序列 vs 实际序列。

附：记忆游戏最小 3D 原型（供本科延申）

已提供两个 C# 脚本（unity/MemoryGameMinimal/）：PlayerController.cs（按 Roll/Pitch 移动小球，键盘模拟）+ MemoryGame.cs（序列展示→输入→判定→成功提示）。暂用键盘模拟，无需美术、无需真机即可跑。

场景搭建（2 分钟）：

  1. Unity 新建 3D（Built-in）工程，建 Scene，存为 Game04_Memory.unity。
  2. Hierarchy：Plane（地面，缩放 2,1,2）、Player（Sphere，置于原点）、3 个 Node（Sphere，分别放左/右/前方向，例如 (-3,0.5,0)、(3,0.5,0)、(0,0.5,-3)），再建一个空物体 GameManager。
  3. 把 PlayerController.cs 挂到 Player；把 MemoryGame.cs 挂到 GameManager，并把 Player 与 3 个 Node 拖进对应字段。
  4. Play：键盘 A/D = 左右(Roll)、W/S = 前后(Pitch)。先看序列高亮，再按顺序开到节点即判定。

键盘 → 真机切换（延申点）：PlayerController 里已留 useIMU 开关与注释；接真机时把 IMUReceiver 挂到场景，将 Player 上的 roll/pitch 来源改为 IMUReceiver 的 latestRoll/latestPitch 即可，游戏逻辑零改动。

事件记录（延申点）：MemoryGame 在 TASK_START / SEQUENCE_SHOW / STEP_CORRECT / SEQUENCE_COMPLETE 处打 Console 日志；后续按统一契约经 UDP 回传 Python，写入 game_event / task_id / trial_id / target / user_response / is_correct / reaction_time_ms。

契约

四个游戏统一数据契约（研究者定，学生不改）

IMU 字段

device_id, timestamp, Ax Ay Az, Gx Gy Gz, Mx My Mz, roll pitch yaw, motion_state, source

统一事件

TASK_START / TARGET_SHOW / ACTION_START / ACTION_END / TASK_SUCCESS / TASK_FAILED / TASK_END

认知指标

task_id, trial_id, target, user_response, is_correct, reaction_time_ms

⚠️ 磁场坑

真机存的是 mx_raw/my_raw/mz_raw（原始计数，非 µT）。Unity 接口须带单位说明；模拟器不要假装自己是 µT，避免真假数据语义不一致。
