魔法岛大冒险 · 四个小游戏玩法设计【定版 v1.0】

适用对象：彦祖（G1+G2）、欢婷（G3+G4）及研究者。本文件基于欢婷《四游戏实现与玩法总结》修改定版，是开发的唯一执行标准。硬件：一根魔法棒（WT901WIFI 九轴 IMU）；引擎：Unity（URP）；数据链：Python → UDP:5005 → Unity，Unity → UDP:5006 → Python（50Hz）。

〇、定版变更摘要（相对欢婷 V0）

欢婷的原稿质量很高（回中判定、参数化、题目审核、混淆变量提醒都保留了）。以下 6 处为定版统一修改，请以此为准：

1. 登录页去"采集化"：原稿"选研究者 + 受试儿童 / 开始采集"改为双入口——儿童点头像即玩、零表单；研究者字段收进齿轮后台。详见第二节。
2. 事件名对齐冻结契约：START → TASK_START，并补齐 TARGET_SHOW（算反应时必需）、ACTION_START、TASK_FAILED、TASK_END。
3. G2"停住"判定纠正：原稿写作"回中判定"有误——G2 是转到精灵处停住，应判角速度静止，不是角度回中（详见 G2）。
4. G3 确认动作锁定：原稿"前倾或晃一下可配置"会导致数据不可比，默认锁定前倾保持；shake 仅备选，且必须记录 confirm_type。
5. 场景命名裁决：统一为语义化命名（下表），不再使用 Game01–Game04。彦祖需把已有场景重命名一次以对齐。
6. G1 认知目标表述：改为"姿态感知与稳定控制（感知平衡）"——既对齐导师的"感知平衡"方向，又避免夸大成"身体平衡训练"。

一、总体流程（一次完整体验）

启动页→ 登录/档案页（双入口）→ 魔法岛主页（4岛+进度星）→ ① 引导→ ② 游戏进行→ ③ 实时反馈→ ④ 回合结算→ 返回主页

四个游戏结构完全一样（引导→玩→反馈→结算四页），只在"游戏进行页"内容不同。结算亮星显示在地图上形成进度。

场景命名（唯一标准，Build Settings 里必须一字不差）：
Start（启动/登录页） · MainMenu（魔法岛主页） · Game1_StarBalance · Game2_FindSpirit · Game3_ForestFriends · Game4_MemoryForest
彦祖现有 Game01/02/03/04 请重命名为上述语义化名称；重命名后更新 Build Settings，全队只保留这一套命名。

二、登录 / 档案页（重点改造：去"采数据感"）

设计原则：孩子和家长看到的界面里不出现"被试 / 编号 / 实验组 / 对照组 / 采集 / Dataset / Session"等研究词。这些字段照记，但只在研究者后台出现。目标是让孩子觉得"我在选我的小精灵开始玩"，而不是"我被登记做实验"。

儿童入口（主界面，默认展示）

  • 页面文案："今天是谁来魔法岛玩呀？"——下方一排卡通头像卡（小兔子、小熊、小猫…）供点选。
  • 孩子点一个头像 → 直接进入魔法岛主页。零输入框、零必填项。
  • 头像与匿名档案（P001…）在后台一一对应，选头像 = 选档案，数据仍存到正确文件夹。
  • 首次使用的头像可由研究者预先建好；孩子不需要知道自己被分配了编号。

研究者入口（右上角齿轮 ⚙，普通孩子不会点）

  • 点齿轮 → 简单 PIN 或长按进入（彦祖实现，PIN 可与研究者约定固定值）。
  • 此页才出现档案字段：participant_id（匿名编号 P00x）、年龄、组别（实验/对照）、惯用手、session_id、数据模式 SIM / REAL。
  • 字段只在后台录入一次，之后自动带入所有 trial；绝不出现在儿童主界面。
  • 设置面板也放这里：灵敏度、确认保持时长 confirmHoldSec、音量、语音提示开关。
数据不受影响：儿童点头像时，Unity 已在后台把 participant_id / session_id / task_id / trial_id 注入事件并经 UDP:5006 回传 CSV。对研究者，数据完整可追溯；对儿童，只有一个头像选择。

三、公共规则（四游戏共用，InputRouter 统一实现）

规则定版定义
回中才算一次棒子歪出去→触发动作，回到中立区那一刻才记为一次有效动作。一直歪着不动永远只算 1 次——防止"抖一串算一串"。
三参数死区 6°（完全不动）· 触发 12°（算一次动作）· 回中容差 5°（回到中立区算回中）。均为可调参数，写进设置面板。
键盘模拟WASD = 前后左右倾斜，Q/E = 水平旋转，空格 = 确认。不接真棒也能全流程玩通（SIM 模式）。
反馈温和做对给星星+鼓励语；做错不批评、不刺耳，给"再试一次"的温柔提示。避免强声光、频繁闪烁、强制倒计时压迫。

这些判定逻辑统一放在 InputRouter（一个脚本），四个游戏都调用它，不要每个游戏各写一套。

四、统一数据契约（锁死，学生不得修改）

1) IMU 每帧（Python → Unity，Unity 只读）：

device_id, frame_id, timestamp, host_timestamp_ms,
Ax Ay Az, Gx Gy Gz, Mx My Mz,   // 磁场真机为原始计数 mx_raw/my_raw/mz_raw（raw counts），非 µT
roll pitch yaw,                 // 单位：度
motion_state, source            // source: SIM / WT901

2) 游戏事件（Unity → Python，7 种，每条带时间戳）：

TASK_START   TARGET_SHOW   ACTION_START   ACTION_END
TASK_SUCCESS   TASK_FAILED   TASK_END
⚠️ TARGET_SHOW 必须在目标出现那一刻打点，ACTION_END 在有效动作完成时打点——reaction_time_ms = ACTION_END − TARGET_SHOW，缺任一个就算不出反应时。

3) 认知任务指标（每条 trial 必记，导师要求的"实际意义"落地处）：

task_id, trial_id,
target,            // 本次目标（如"蓝色精灵" / "左→右→前"）
user_response,     // 儿童实际选择/动作序列
is_correct,        // 对错
reaction_time_ms,  // 反应时长
game_event,        // 上述 7 种事件
confirm_type       // G3 用：hold / shake（默认 hold）

记录分工：注意力记"找对没+反应时"；社交记"选了啥+提示几次"；记忆记"目标序列 vs 实际序列+正确率"；感知平衡记"稳定保持时长+超出次数"。

五、四个游戏（定版玩法）

G1 星星平衡岛 场景：Game1_StarBalance · 负责：彦祖

认知目标：姿态感知与稳定控制（感知平衡）——用小幅、稳定的倾斜把手中的"星星"稳住。（注意：这是手部精细姿态控制，不是全身平衡训练，对外表述避免夸大。）

怎么玩：星星在屏幕顶端架子上，玩家左右/前后慢慢倾斜魔法棒，星星随之滚动；用小幅度稳定的力量把星星推进中间圆圈并稳住 2 秒，星星亮起即成功。晃太猛星星滚出去要重来。

实现要点：读 roll/pitch → 转星星移动速度（死区内不动）→ Rigidbody2D 施力；判定 = 位置在圈内 + 持续 2 秒；难度 = 圈变小 / 加风力干扰 / 时间变短。

记录：稳定保持时长、超出目标圈次数、是否成功、用时。

G2 寻找魔法精灵 场景：Game2_FindSpirit · 负责：彦祖

认知目标：持续注意力 + 水平方向搜索控制。

怎么玩：精灵藏在场景转盘/花丛后，玩家水平左右转棒（像转方向盘），视角随之转；当精灵出现在视野中央时停住不动 1 秒，精灵跳出。找到指定数量过关。

定版纠正："停住"用角速度静止判定——|Δyaw/Δt| < 阈值 持续 1 秒；不是要求棒子回到正前方（那与"转到精灵处停住"矛盾）。水平旋转用 yaw 累计值，不要用 roll/pitch。

实现要点：yaw 累计 → 映射视角/转盘角度；精灵进入视野中心区 + 角速度静止 1 秒 → 找到；难度 = 位置更偏 / 数量增多 / 加相似干扰物。

记录：target（哪个精灵）、is_correct、reaction_time_ms、误触次数。

G3 帮助森林伙伴 场景：Game3_ForestFriends · 负责：欢婷

认知目标：情景理解与选择决策（社交）。

怎么玩：出现情景卡（如"小兔子迷路了"）+ 3 个选项卡；玩家左右倾斜棒切卡（切一张必须先回中才能切下一张），选中卡放大高亮；再向前倾并保持 1 秒确认。答对伙伴开心，答错温柔提示"再想一想"。

内容审核硬门槛：情景题必须存 JSON，且每题必须带 reviewed_by / review_date 字段；无审核人信息的题目不允许载入正式版。题目内容须经专业（特教/心理）人员审核后使用。

确认动作定版：默认锁定前倾保持（confirmHoldSec，与 G1 同族连续姿态、可量化）；shake 仅作备选配置，若启用必须在数据里写 confirm_type=shake，否则数据不可比。

记录：目标情景 id、user_response（选项序号）、is_correct、reaction_time_ms、提示次数、confirm_type。

G4 魔法记忆森林 场景：Game4_MemoryForest · 负责：欢婷

认知目标：工作记忆（记住并复现顺序）。

怎么玩：屏幕上 3 个蘑菇依次亮起（如 左→右→前 = L-R-F），玩家看完后用棒按同样顺序做动作复现；做对亮一格灯、连续答对进下一难度（序列变长），做错重看演示。

数据解读提醒：做错可能是手部控制没做好，不一定是记不住。分析时不能仅凭对错下"记忆差"的结论——要结合 ACTION_END 的动作轨迹判断。

实现要点：演示阶段（蘑菇依次亮+音效）→ 输入阶段（复用 G1–G3 同一套 Left/Right/Forward/Back 动作判定）；每个动作 S0→S1→S2 闭合记一次；输入阶段 10 秒没动给提示。

记录：target（目标序列）、user_response（实际序列）、is_correct、尝试次数、错误位置。

最小原型必须验证三件事：① 快速抖 10 下最多算 2 次动作；② 一直歪着 5 秒只算 1 次；③ 序列比对正确。

七、验收标准（DoD，交付前逐条自查）

  • □ 四个场景名与第一节完全一致，Build Settings 里只保留这一套；
  • □ 儿童入口无任何研究词表单；研究者字段只在齿轮后台出现；
  • □ SIM 模式（键盘 WASD/QE/空格）下四个游戏都能从引导玩到结算；
  • □ 7 种事件全部按契约触发，TARGET_SHOW 与 ACTION_END 时间差能算出反应时；
  • □ 回中判定生效：一直歪着不重复计次（G4 原型三件事全过）；
  • □ G2 用角速度静止判定，不是角度回中；
  • □ G3 所有正式题目都带 reviewed_by / review_date；
  • □ 结算页亮星同步到主页地图进度；
  • □ 不宣称"改善注意力/记忆/社交"等疗效——只记录行为表现。
研究边界：儿童游戏是 IMU 研究的一个应用验证场景，主线仍是 Calibration → Motion State → Qa/Qm → Adaptive Fusion。最终产出 = IMU 原始数据 + 认知任务 + 动作事件 + 任务表现，四类可关联信息。
