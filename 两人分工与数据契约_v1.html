两人分工与数据契约 v1（转发给两位本科生）

项目：《魔法岛大冒险》九轴游戏化多运动状态 / 认知训练数据采集系统。本文件规定工作模型、本周任务、统一数据契约、协作硬规则。游戏具体玩法仍在与导师确认中，本周不要求做完整游戏。

一、工作模型（核心结论）

不是两个人共做一个游戏，也不是各做一个独立工程。正确做法是：一个共享 Unity 工程 + 彦祖先修框架 + 设计锁定后每人认领 2 个游戏。
同一 Unity 工程→ 彦祖搭框架(本周)→ 设计锁定→ 彦祖: 游戏1+2+ 同学: 游戏3+4

四人（师姐 + 彦祖 + 另一同学）角色：

角色负责
师姐(研究者)总体设计、IMU 数据层(Python)、科研需求、统一接口与数据契约（本文件）
彦祖Unity 主工程骨架、开始/被试/主菜单、IMU 接入壳、事件系统；设计锁定后做游戏1+2（连续姿态控制类）
另一同学四个游戏设计稿 + 1 个最小原型；设计锁定后做游戏3+4（离散状态/序列类）

为什么这样分：游戏1(平衡)、游戏2(注意力)都是连续姿态控制，Roll/Pitch/Yaw 平滑处理可复用；游戏3(社交)、游戏4(记忆)都是离散状态/序列判断，选项选择、动作确认、顺序记录可复用。按"连续 vs 离散"分组，代码复用最自然、工作量最均衡。

二、本周任务（设计未定稿，只做框架+设计+2个原型）

彦祖 Unity 主工程框架 V0.1

  • 建统一 Unity 工程（建议名 MagicIsland_IMU_Game），目录按 Scenes / Scripts(Core,UI,IMU,Game) / Prefabs / Materials 整理。
  • 完成开始界面（《魔法岛大冒险》+ 开始/设置/退出）、被试信息界面（编号/年龄/游戏编号/trial/左右手/数据模式 SIM·REAL，无数据库，场景间传递即可）、主菜单（4 个游戏入口按钮，先跳统一测试场景）。
  • 用 IMUReceiver.cs 正式验收：Python 模拟器 → UDP → Unity Cube 旋转（Roll→X, Pitch→Z, Yaw→Y）。

另一同学 认知游戏设计 + 1 个原型

  • 围绕四个方向各写一页设计说明（游戏目标 / 认知训练目标 / 操作方式 / 反馈 / 难度 / 记录指标）。
  • 做一个最小 3D 原型（建议记忆游戏）：小球/角色 + 按 Roll/Pitch 移动 + 到达终点判定 + 成功提示，暂用键盘模拟，不需美术。

师姐 本周定四游戏的认知训练目标细化 + 维护 Python 数据层与统一接口。

三、统一数据契约（锁死，学生不得自行修改）

1) IMU 每帧字段（来自 Python，Unity 只读）：

device_id, timestamp,
Ax Ay Az, Gx Gy Gz, Mx My Mz,   // 注意：Mx/My/Mz 真机为原始计数(raw)，非µT，接口须带单位说明
roll pitch yaw,
motion_state, source              // source: SIM / WT901

2) 统一游戏事件（Unity 经 UDP 回传 Python，每条带时间戳）：

TASK_START  TARGET_SHOW  ACTION_START  ACTION_END
TASK_SUCCESS  TASK_FAILED  TASK_END

3) 认知任务指标（导师要求的"实际意义"落地处，必须记录）：

task_id, trial_id,
target,            // 本次目标(如"蓝色精灵"/"左→右→前")
user_response,     // 儿童实际选择/动作
is_correct,        // 对错
reaction_time_ms   // 反应时长

⚠️ 注意力：记"找对没、反应时"；社交：记"选了啥、提示几次"；记忆：记"目标序列 vs 实际序列、正确率"。否则只有九轴数据却无法关联认知任务表现。

四、协作硬规则

  • 同一工程，Git 分支：彦祖建主工程并初始化 Git；每人开自己的分支，禁止各建独立 Unity 工程。
  • 统一接口：所有游戏共用同一套 JSON 字段名、同一套 event / motion_state 命名，由师姐规定。
  • 统一 UI 规范：卡通风格、大按钮少文字、清晰图形/语音提示、星星/小红花正向反馈、难度可调；避免强制倒计时、强声刺激、频繁闪烁（孤独症儿童个体差异）。
  • 不宣称认知疗效：游戏可训练并记录行为，但不得声称仅凭 IMU 数据证明了注意力/记忆/社交改善——那是后续评估的事。

五、研究边界提醒

儿童游戏是师姐 IMU 研究的一个应用验证场景，不是把研究方向转向认知训练算法。主线仍是 Calibration → Motion State → Qa/Qm → Adaptive Fusion。游戏最终要产出：IMU 原始数据 + 认知任务 + 动作事件 + 任务表现 四类可关联信息。
